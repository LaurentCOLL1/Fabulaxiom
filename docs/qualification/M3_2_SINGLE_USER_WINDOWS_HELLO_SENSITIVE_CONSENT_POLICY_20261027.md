## Périmètre de la nouvelle candidate, NON QUALIFIÉ avant CI exacte

1. `src-tauri/src/m32_sensitive_action_consent_tests.rs` est **exclusivement importé par `#[cfg(test)]`** dans `lib.rs`. C'est un banc de politique déterministe **en mémoire** ; il **n'appelle aucune API Windows Hello**. `TrustedOsOutcome::Verified` y est une valeur de simulateur ; elle **ne doit jamais** devenir un champ IPC ou une preuve envoyée depuis React.
2. Les types `ExactIntent` fixent **l'action sensible**, un **identifiant de ressource fictive** et l'**empreinte de sa révision exacte**. Après une demande, il faut une unique réponse positive du vérificateur natif dans une fenêtre fictive de 30 secondes, puis **revalidation du gate et du préflight au moment de l'application**. Toute réponse non positive, ticket absent, délai dépassé, horloge incohérente, substitution d'action/cible/révision, demande parallèle et tentative de réutilisation est **refusée**, le ticket étant consommé même en échec. Aucun chemin Windows ou SQLite privé dans ces tests.
3. Onze tests Rust nouveaux testent ces décisions. Un garde textuel contrôle le module test-only et l'absence d'IPC/SQLite/WinRT réel. Un contrat de continuité lie le périmètre à la décision produit. **Cibles attendues, pas résultats anticipés : 165 Rust, 7 Greenfield, 36 gardes, 128 contrats.**
4. Les opérations *éventuellement* soumises à Hello, **uniquement après autorisation distincte et implémentation des gates** : correction de chronologie manuelle, restauration de sauvegarde, activation d'une nouvelle v7 et suppression de projet. La lecture, navigation et saisie ordinaire ne demanderaient pas Hello. Les quatre opérations sont **noms de simulation**, aucune n'est disponible via une commande Tauri nouvelle.

## Intégration future, expressément NON implémentée ici

1. Une commande backend source de confiance, propriétaire de l'intention exacte, applique toutes les autorisations et sécurités SQLite **avant** de demander Hello et **immédiatement avant** la mutation, sans s'en remettre à un état React ou à un `verified=true` IPC.
2. Sur Windows desktop, `UserConsentVerifier.CheckAvailabilityAsync()` puis **interop HWND** `IUserConsentVerifierInterop::RequestVerificationForWindowAsync(...)` / variante .NET `UserConsentVerifierInterop.RequestVerificationForWindowAsync(hwnd, message)`. La méthode UWP `RequestVerificationAsync` ordinaire n'est pas la voie desktop. **L'API Win32 interop référencée indique Windows build 22000 minimum ;** vérifier la compatibilité OS de Fabulaxiom avant activation, sans présumer un fallback silencieux Windows 10.
3. Interruption, indisponibilité, absence de configuration, politique Windows, erreur d'interop ou délai dépassé : **STOP**, affichage d'un motif non secret et possibilité de réessayer comme **nouvelle opération** ; jamais mot de passe Fabulaxiom alternatif automatique.
4. Le backend doit considérer un résultat `Verified` comme une **confirmation humaine locale à un instant donné**, pas une attestation d'identité multi-utilisateur, pas une signature durable ni une preuve de l'unicité du writer. Un autre processus du **même utilisateur Windows** peut toujours ouvrir des fichiers auxquels il a droit. L'UI Hello ne rend pas SQLite chiffrée ni `xOpen` atomique.
5. Avant le premier vrai dialogue Windows Hello ou une mutation opérateur, re-présenter l'étendue exacte du changement, le chemin Windows, les effets, la disponibilité et les STOP, et recueillir l'autorisation spécifique nécessaire. Aucun appel OS/GUI sur la machine du propriétaire dans cette PR.

Sources officielles : [Microsoft `UserConsentVerifier`](https://learn.microsoft.com/en-us/uwp/api/windows.security.credentials.ui.userconsentverifier), [`RequestVerificationForWindowAsync` Win32](https://learn.microsoft.com/en-us/windows/win32/api/userconsentverifierinterop/nf-userconsentverifierinterop-iuserconsentverifierinterop-requestverificationforwindowasync), [résultats vérification](https://learn.microsoft.com/en-us/uwp/api/windows.security.credentials.ui.userconsentverificationresult), [interop bureau](https://learn.microsoft.com/en-us/windows/apps/develop/ui/display-ui-objects).
