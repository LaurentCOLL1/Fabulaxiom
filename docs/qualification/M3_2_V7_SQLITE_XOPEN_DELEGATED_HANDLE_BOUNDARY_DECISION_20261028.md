## Actual decision: four requirements, not one green-path test

1. **Exact file identity at SQLite VFS handoff.** A path/parent/FILE_ID_INFO checked before `xOpen` can be substituted before the default Win32 VFS opens the name. A *test-only* VFS wrapper now asks the **already delegated `sqlite3_file`** for `SQLITE_FCNTL_WIN32_GET_HANDLE` through its `xFileControl` inside the same `xOpen` callback, compares the **volume serial + 128-bit FileId** to an expected disposable handle, and returns `SQLITE_CANTOPEN` after calling delegated `xClose` on mismatch. No SQLite caller receives a successful open for the controlled swapped identity. This closes the demonstrated gap **between precheck and xOpen return**, but the underlying OS open still takes place before veto; it is **not atomic pathname binding** and cannot immunize the namespace against privileged rename, file access during the open, or arbitrary uncooperative VFSes. No `V7WriterAdmission` token is minted.
2. **Ownership and OS namespace.** A2 named mutex coordinates only cooperating Fabulaxiom processes. A production security descriptor, per-SID/session name, DACL checks and namespace protection remain independent unproven prerequisites. Default A0 refuses cross-process EXISTING_PROFILE. `WAIT_ABANDONED` requires recovery and is not a clean shutdown proof.
3. **SQLite lineage and sidecars.** A3 integrity_check and separate foreign_key_check, schema provenance, recovery and `-wal`/`-shm`/journal handling must be evaluated on the *same* admitted handle and all mapped sidecars. The current negative fixtures veto invalid/ambiguous states but cannot authenticate a real database or prove a successful restart/recovery. An ephemeral clean-close observation is insufficient across processes.
4. **Writer exclusivity and lifecycle.** Even exact main-file FileId in `xOpen`, A2 cooperation, and A3 structural consistency do not exclude an uncooperative external SQLite writer or guarantee an OS-atomic custody transition across main/WAL/SHM and ancestors. The current worker has only an already-admitted input concept and cannot be activated. Writer stays `NOT_PROVEN`.

**Decision:** keep the test-only delegated-handle veto as a falsifiable safety boundary and select **fail-closed runtime A0** until (1) a production-owned VFS/session design binds the real handle and sidecars with verified ACL/namespace and lifecycle, (2) external writer exclusion or an explicit trust/threat-model acceptance is independently reviewed, (3) same-profile provenance/recovery is proven, and (4) a distinct owner gate authorizes the application writer. No claim of a fully atomic SQLite open. Avoid adding path-only prechecks as a substitute.
